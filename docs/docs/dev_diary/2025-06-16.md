## 1. Hotfix na prod

O sistema atual apenas verifica o weather_id para decidir se vai prever algo ou
não. Isso gera situações de uma chuva muito fraca gerar previsão, o que causa
alguma confusão nos usuários.

```python

        if not (500 in df['weather_id'].values or 501 in df['weather_id'].values or 502 in df['weather_id'].values or 503 in df['weather_id'].values or 504 in df['weather_id'].values or 521 in df['weather_id'].values or 522 in df['weather_id'].values or 312 in df['weather_id'].values or 314 in df['weather_id'].values or 201 in df['weather_id'].values or 202 in df['weather_id'].values or 232 in df['weather_id'].values):
```

A mudança é bem simples e baseia-se na distribuição de acumulado de precipitação
diária. Vou utilizar o valor da mediana como corte e decidir não fazer previsão
alguma quando a precipitação acumulada prevista for menor que a mediana.

## 2. Mudança de arquitetura

Inicialmente, a ideia era do floodcast ser a API do sistema e, ao mesmo tempo,
fazer a inferência dos modelos. Após uma conversa com o Tiago, decidimos 
separar esse módulo em dois: o floodcast continua como apenas um módulo de 
inferência, a ser executado em um cronjob e agora temos um novo módulo para 
servir a API. Esse novo módulo se chamara **sentry**.

Pronto, agora podemos seguir para o módulo de inferência.

## 3. Implementação do floodcast

No harvest eu criei uma abstração a fim de modularizar o chamado para APIs
externas. No floodcast eu não vou seguir essa lógica de abstração. O motivo é 
simples: eu ainda não sei como vai ser a interface para os novos tipos de 
modelos que vamos usar. Quando não sabemos o que vem pela frente, toda 
abstração pode sair pela cultara (ver [premature
abstraction is the root of all
evil](https://arendjr.nl/blog/2024/07/post-architecture-premature-abstraction-is-the-root-of-all-evil/))

Sendo assim, esse módulo vai ser (quase) tão simples quanto a versão original.

As principais diferenças:

* Não mais precisar do arquivo de modelo junto com o código fonte. Vou
utilizar, a princípio, o google drive, mas vou provisionar também para que mais
para a frente implementemos uma função que acesse o MinIO para pegar esse modelo
* Adequar o pré-processamento para a versão paga da API da Openweather
* Fazer a inferência dos diversos modelos em paralelo

Vamos, então, por partes.
